# Contributing

1. Open an issue documenting scope and acceptance criteria.
2. Work on a short-lived branch and submit a pull request.
3. Add or update tests for behavior changes; prefer deterministic fixtures.
4. Make security/compliance implications explicit (particularly extraction, PII, auth and outbound webhooks).
5. Merge only after required checks pass and protected-branch requirements are satisfied.

Use Conventional Commit prefixes when practical (`feat:`, `fix:`, `docs:`, `test:`, `ci:`). Avoid adding services without a documented owner and deployment strategy.
